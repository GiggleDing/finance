# 账本透视

把「钱迹」记账 App 导出的账单，变成能看资产、看趋势、给建议的个人财务看板。

钱迹记账很顺手，但分析能力有限——分类统计只能看单月，资产和投资的联动看不出来。这个项目是它的**分析层**：数据仍然在钱迹里记，这里只负责读懂、算清、说人话。

## 数据流向

```
钱迹 App 导出账单 (xlsx/csv)
        ↓  手动导入
解析与清洗 → 按 ID 去重 → 用 DEK 加密 → 浏览器 IndexedDB（只有密文）
        ↓  解锁后解密进内存
计算引擎（收支统计 / 分类下钻 / 投资月度）
        ↓
资产快照 · 报表 · 投资 · 流水 · 数据体检
```

**没有后端，没有服务器，没有账号。** 数据只存在你自己浏览器的 IndexedDB 里，
而且**是加密存的**，不会上传到任何地方。
代价是：换设备、换浏览器、清缓存都会丢数据 —— 所以「数据」页提供**加密备份**的导出/导入。

## 加密模型（改这块代码前必须读懂）

GitHub Pages 是纯静态托管，没有服务端。这意味着两件事：
页面是公开可访问的，而且任何「访问控制」都只能在浏览器里做。
所以这里做的不是「拦住访问」，而是**加密数据本身** —— 密码不是门锁，是钥匙。

| 环节 | 做法 | 为什么 |
|---|---|---|
| 密钥结构 | **信封加密**：随机 32 字节 DEK 锁数据，密码只负责「包住」DEK | 改密码只需重新包一次 DEK（毫秒级），不用重新加密整个库，也不会出现「改到一半两头不靠」 |
| 密码 → 密钥 | PBKDF2-HMAC-SHA256，**60 万次迭代** + 16 字节随机盐 → 派生 KEK | OWASP 对 SHA-256 的建议下限。这个数字只决定「猜密码的代价」 |
| 数据加密 | AES-256-GCM，每次加密都用**全新随机 IV**，并带 AAD 绑定用途 | GCM 自带认证标签，密文改一个字节就解不开；AAD 让密文无法被挪到别的用途上 |
| 落盘形态 | IndexedDB 里只有两张表：`meta`（信封）和 `vault`（一个整库密文块） | 逐条加密而索引明文等于没加密 —— 裸库看索引就知道你哪个月花了多少 |
| 恢复码 | 24 位 / 120 bit，字母表剔除 `0 1 O I`（保留 L，32 个符号正好 5 bit 一个） | 忘了密码时用它可以重置。它等同于一把钥匙，必须和密码分开存放 |
| 会话 | 解锁后把**裸 DEK** 放进 `sessionStorage` | 刷新页面不用重输密码，关掉标签页即蒸发。存 DEK 而不是存密码 —— DEK 只开本地这个保险箱，密码还能开所有历史备份 |
| 备份文件 | 每个备份**自带独立的盐和迭代数**，不依赖本机保险箱 | 备份能脱离保险箱单独打开；**改主密码不会让旧备份失效**（旧备份仍用它导出当时那个密码） |
| 密码强度 | 设密码时用 `src/core/password.ts` 卡强度门槛（≥10 位、估算 ≥50 bit、拒绝常见词与日期形态） | PBKDF2 提高的是「每次猜测的成本」，完全不改变「密码本身有多好猜」 |

### 必须记住的两条

1. **忘记密码 = 本机数据打不开**。要么用恢复码重置，要么用备份文件恢复。
   能重新拿回来的只有钱迹导出的流水；手动录入的账户余额快照会一起丢。
2. **旧备份用旧密码打开**。备份自带盐，所以它记的是「导出那一刻的密码」，
   不是「当前的密码」。把备份和它的密码一起写进密码管理器的备注里。

### 已知边界（不假装能防住）

- **同源共享**：`<用户名>.github.io` 下如果还有别的项目，那个页面的脚本理论上能读到
  `sessionStorage` 里的 DEK。要彻底避免只有两个办法：不共享会话（把解锁改成刷新即锁），
  或者把站点挂到独立域名下。
- **XSS 等于全盘失守**：内存里就有一把能解开整库的钥匙。所以生产构建注入了严格 CSP、
  关闭 sourcemap、剥离 console，并且不引任何第三方脚本或 CDN。
- **KDF 参数**固定在代码里，没有做成可配置项 —— 一个能被配置调低的迭代数迟早会被调低。

## 统计口径（这是本项目的核心，改代码前请先读这里）

钱迹导出的「类型」列有 **10 种取值**，不是只有收支转账三种。统计口径由 `src/core/classify.ts` 单点决定：

| 钱迹类型 | 归一化 | 计入收支？ |
|---|---|---|
| 支出 | `expense` | ✅ 计入支出 |
| 收入 | `income` | ✅ 计入收入 |
| 转账 | `transfer` | ❌ 账户间搬运；用于识别投资投入 |
| 债务-还款 | `debt_repay` | ❌ 单列还贷 |
| 债务-借入 / 借出 / 收款 | `debt_*` | ❌ 单列债权债务 |
| 退款 | `refund` | ⚠️ 作**支出冲减**（负数），不能当收入 |
| 报销 / 报销记录 | `reimburse` | ⚠️ 作**支出冲减**，不能当收入 |

其他硬规则：

- **金额恒为正数**，收支方向只看「类型」列，绝不靠正负号。
- **去重靠 ID**。钱迹的账单 ID 天然唯一，重复导入同一份文件不会产生重复数据。
- **有效记账窗口从 2026-02 起**。更早的月份每月只有 1 条记录（车贷月供的历史补齐），
  混进趋势图会看成「常年为零然后突然暴涨」。同比环比也因为缺去年同期数据而不做。
- **资产总览用手动快照，不从流水推算**。导出里没有期初余额，基金账户也不跟随净值波动，
  推算出来的余额一定是错的。
- **投资只报投入和收益，不算收益率**。钱是分批投进去的，没有每笔的买入时点和份额，
  「累计收益 ÷ 累计投入」这种比率没有意义。

## 投资模块怎么用

- **每月投入**：自动识别——「转账」且资金流入「基金」账户。
- **每月收益**：你在钱迹里记一笔「收入」，账户选「基金」，金额填当期收益。
  下次导入账单时会自动带上，不需要在这个页面另外填。
- 余额宝/零钱通的「利息」收入会被单独归为货币基金收益，不会混进投资组合收益里。

## 本地开发

```bash
npm install
npm run dev        # 开发服务器
npm test           # 回归测试（统计口径 + 加密层的护栏）
npm run build      # 生产构建（含 CSP 注入、剥离 console、关闭 sourcemap）
```

技术栈：React 18 + TypeScript + Vite · Dexie(IndexedDB) · Web Crypto · ECharts · SheetJS · Tailwind CSS

测试分三层：
- `tests/crypto.test.ts` —— 密码学原语（IV 不复用、篡改检测、AAD 绑定、恢复码编码无偏）
- `tests/password.test.ts` —— 强度门槛（常见词、纯数字、日期形态、键盘序列）
- `tests/vault.test.ts` —— 保险箱全流程（迁移、跨刷新会话续期、改密码、恢复码重置、备份端到端、"磁盘上搜不到明文"）

`tests/vault.test.ts` 跑在 `fake-indexeddb` 上，走的是真实生产代码路径，含真实的 60 万次 PBKDF2。

## 部署

推送到 `main` 分支后，GitHub Actions 会自动跑类型检查、回归测试、构建，并发布到 GitHub Pages。

仓库需要在 **Settings → Pages → Source** 里选择 **GitHub Actions**。

构建用相对路径（`base: './'`），因此放在 `https://<用户名>.github.io/<任意仓库名>/` 下都能正常访问。

## 隐私

- 账单文件和余额数据**绝不应该提交进仓库**，`.gitignore` 已排除 `*.xlsx` `*.xls` `*.csv`
  以及引用本机真实账单路径的 `*.local.test.ts`。
- 代码里不硬编码任何真实账户或金额。
- 免费版 GitHub Pages 只能用公开仓库，所以**页面本身是公开的** —— 但页面里没有数据：
  数据在你浏览器的加密保险箱里，别人打开这个网址只会看到设置密码页。
- `.qa/`（本地截图与冒烟脚本）、`.workbuddy/`（工作区记忆，含财务分析结论）、
  `deliverables/` 同样不入库。

## 建议引擎的边界

只输出最多 3 条，且每条都能从原始记录复算、能下钻核对。

明确**不做**的伪洞察：收益率与年化、有效窗口之前的趋势、基金买卖择时、「跑赢基准」对比、
未来现金流预测、「理财收益能力」评估、泛泛的省钱话术。
